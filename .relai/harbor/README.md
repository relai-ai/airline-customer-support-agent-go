# RELAI Harbor runtime

This directory is generated by `relai init`.

`agent.toml` names the leaf command that runs once inside each Harbor trial. The CLI-owned launcher sends every turn as one newline-delimited JSON request and requires one newline-delimited JSON response containing `assistant_message`; stdout is reserved for this stream. Build a reusable project adapter that maps that stream to the target's evidenced native lifecycle (persistent object, history replay, or an external session). Use configure_harbor_packaging in managed mode to generate the task Dockerfile before manually authoring an image definition. Instrumentation must atomically update the complete canonical ATIF-v1.7 document at `RELAI_ATIF_TRAJECTORY_PATH`; the generic launcher never derives trajectory events from stdout. Atomic replacement alone is not safe for overlapping async event callbacks: use one in-process writer queue or lock to serialize every snapshot's read, append, and replacement; use a unique same-directory temporary path for every write; and drain pending writes before each turn response and before adapter exit, including errors and cancellation. Each completed snapshot must retain the ordered cumulative prefix across turns.

During the Harbor agent phase, RELAI mounts one fresh sanitized snapshot of current project source read-only at `/workspace`. It omits sensitive paths (including `.env` and `.env.example`), `.git`, `.relai`, transient Wiki views, and host dependency roots such as `.venv` and `node_modules`; changes made after snapshot creation are not reflected in that run. The adapter must import or invoke project source from `/workspace`, rather than a copied project source in a task environment. The mount is unavailable during Docker builds. Task images own the adapter, task scenario and services, evaluator, dependencies, and build output. Dockerfiles must not copy project source from the checkout or run installs against `/workspace`: install toolchains and external dependencies reproducibly from staged lockfiles in runtime setup, without host `.venv` or `node_modules`. Installs and builds that need current source, such as local or workspace packages, editable installs, and compilation, belong in managed workspace setup, which runs once per run against a writable copy of the snapshot before trials mount the result read-only. Private-registry credentials for runtime and workspace setup are declared by name as install secrets; their values stay in `.relai/simulator.env` or the environment. Preserve any old copied project source but do not select it or put it ahead of `/workspace`, where it can shadow the mounted source.

The CLI owns the canonical bridge and persistent trial launcher. Do not edit those files to repair instrumentation; configure a separate leaf project adapter under `.relai/harbor/adapter/`. Task authors declare evaluators in each task's `task.toml`: code evaluators run in the verifier `tests/evaluate.py`, and LLM judges are `tests/evaluator.toml` manifests with a rubric. `relai init --restart` restores the CLI-owned assets automatically.

New tasks keep Harbor-required `instruction.md` empty. Author scenario inputs and evaluator criteria in their task assets; preserve any existing authored instruction text.

Runtime credentials belong in `.relai/simulator.env` and are forwarded only to Harbor's agent phase.

On SELinux-enabled Docker daemons, RELAI requests a shared container relabel only for a disposable per-run workspace snapshot under `.relai/tmp`; it never relabels checkout content or masks. It labels only the new CLI-owned Harbor job directory for container writes.
