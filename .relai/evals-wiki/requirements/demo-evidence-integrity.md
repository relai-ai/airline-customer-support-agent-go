# Ground demo claims in measured evidence

Do not present installation, image builds, or unit checks as proof of live demo readiness. Verify real startup, prerequisites, authentication, plugin availability, and the full live loop before readiness claims. Use the rehearsed revision; production E2B must pin a verified build rather than a mutable alias.

Do not describe suspicious code paths or unverified challenges as demonstrated agent failures. Record checkpoint, scenario, model profile, command, trajectory, and valid evaluated outcome before changing challenge status. Report passing baselines honestly as resilience evidence. Do not alter expected behavior or evaluators merely to obtain a pass.

Label recorded fallback results as recorded; limited regression results do not prove universal reliability.
